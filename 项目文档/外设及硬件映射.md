# 外设及硬件映射

> 事实来源：`Robot_Chassis_Arm.ioc2` 与 `generated/hal/` 生成代码（2026-11-27 核对）。
> 本文件只记录"现在是什么"和"还缺什么"，具体值以 `.ioc2` 为准。

---

## 1. 已配置外设

| 外设 | 引脚 | 关键参数 | 中断/滤波现状 |
|---|---|---|---|
| FDCAN1 | TX=PB9，RX=PB8，AF9 | 经典 CAN，1 Mbps，采样点 87.5%，normal 模式 | 生成代码未开 NVIC；`std/ext_filters_nbr=0`，不匹配帧全部进 RX FIFO0。设计上由 Platform 层初始化时启动并使能 RX FIFO0 中断（未实现） |
| FDCAN2 | TX=PB13，RX=PB12，AF9 | **FD + BRS**，1 Mbps / 2 Mbps，Tx 延迟补偿 offset=10 | 同上，当前未启动 |
| USART2 | TX=PA2，RX=PA3，AF7 | 115200，8N1，无流控 | 无 DMA、无 IDLE 中断 |
| USART6 | TX=PC6，RX=PC7，AF7 | 115200，8N1，无流控 | 无 DMA、无 IDLE 中断 |
| TIM6 | — | HAL 1 ms 时基（`stm32_hal_timebase.h`） | **已被系统占用，不能再做 PWM/编码器** |
| ICACHE / MPU / NVIC | — | ICACHE 已启动；NVIC 仅设置优先级分组 4 | 无任何外设 IRQ 使能（CAN 由运行时补上） |

引脚总表：PA2/PA3、PB8/PB9、PB12/PB13、PC6/PC7，加 SWD（PA13/PA14）与 HSE（PH0/PH1）。

## 2. 尚未配置的资源

| 缺口 | 影响 | 结论 |
|---|---|---|
| 无 GPIO 输出 | 没有 DIR / EN / 限位 / 急停 | 若电机走 CAN 总线则不需要；走脉冲则必须补 |
| 无 PWM / STEP 定时器 | 无法发脉冲 | 取决于是"总线步进"还是"脉冲步进"（H-1） |
| 无编码器定时器 | 无法直接读增量编码器 | 若驱动器自带闭环并回传位置则不需要 |
| 无 DMA 通道 | 串口只能轮询或逐字节中断 | IMU 与上位机链路落地前必须补 |
| 无第三个串口 | 上位机 + 遥控 + IMU 三选二 | 见第 4 节 |
| 无 ADC | 无法测电池电压 | 需求未提，列为可选项 |

## 3. 板级映射表（`bsp/board_config.h`）

| 宏 | 当前值 | 含义 | 状态 |
|---|---|---|---|
| `BOARD_MOTOR_COUNT` | 4 | 轮序 FL / FR / RL / RR | 固定 |
| `BOARD_MOTOR_BUS` | `PLATFORM_CAN_BUS_1` | 四路步进挂 CAN1（经典 1 Mbps） | **待确认 H-2** |
| `BOARD_MOTOR_NODE_ID_FL/FR/RL/RR` | 1 / 2 / 3 / 4 | 对应驱动器菜单 `ID_Addr` | **待确认 H-3** |
| `BOARD_WHEEL_DIAMETER_MM` | **0.0f** | 麦轮直径，mm | **待实测 H-4** |
| `BOARD_MOTOR_COUNTS_PER_REV` | 3600.0f | X 固件位置单位 0.1°，一圈 3600 计数 | 依固件而定 |
| `BOARD_MOTOR_ACCEL_RPM_S` | 1000 | 加速度，RPM/s；0 表示用驱动器默认 | 待整定 |
| `BOARD_MOTOR_TIMEOUT_MS` | 100 | 反馈超时判离线 | 待整定 |
| `BOARD_MOTOR_DIR_INVERT_FL/FR/RL/RR` | 0 / 0 / 0 / 0 | 1 = 该轮方向取反 | **待联调 H-5** |
| `BOARD_IMU_UART_INSTANCE` | 0 | IMU 串口 | 占位，H-6 |
| `BOARD_HOST_UART_INSTANCE` | 0 | 上位机串口 | 占位，H-6 |
| `BOARD_RC_INTERFACE` | 0 | 遥控接口形态 | 占位，H-7 |

**重要约束**：`BOARD_WHEEL_DIAMETER_MM = 0.0f` 表示轮径未标定，驱动层必须拒绝运动且不发帧——用猜测的传动比驱动底盘比不动更危险。这是刻意设计的失败安全，不是 bug。

## 4. 通道分配冲突

需求有三个串口级设备，硬件只有两个可用串口：

| 设备 | 建议 | 备选 |
|---|---|---|
| 上位机（ROS 2 桥） | USART6（PC6/PC7），115200 | USART2 |
| 遥控接收机 | USART2（PA2/PA3） | 若为 SBUS 需 100000 8E2 + 反相 |
| IMU | **无可用串口** | ① 新增 USART1/USART3；② 若驱动器/IMU 支持 CAN 则挂 CAN2；③ 换 SPI/I2C 型号 |

总线侧的冲突：

- CAN1 是**经典 CAN 1 Mbps**，CAN2 是 **FD + BRS 1M/2M**。
- 多数步进驱动器只支持经典 CAN。**若电机接 CAN2，需要先把 CAN2 改成经典 CAN**（H-2）。
- 两个总线目前都没有验收滤波器，总线上所有帧都会进中断。四电机 + 机械臂共总线时建议按 ID 段加滤波。

## 5. 引脚与定时器约束

- TIM6 被 HAL 时基占用，不能复用。
- 若最终走脉冲方案，需要：4 路 STEP 定时器通道 + 4 路 DIR/EN GPIO + 4 路编码器接口。C593 的定时器数量够，但引脚需要重新规划，且与现有 CAN/串口引脚可能冲突。
- 现有 8 个通信引脚已固定，不建议再动。

## 6. CubeMX 重生成检查清单

`.ioc2` 是唯一事实来源，重新生成后必须逐项确认：

| 检查项 | 位置 | 期望 |
|---|---|---|
| 用户代码构建入口 | `CMakeLists.txt` | `include(cmake/user.cmake)` 仍在 |
| 栈溢出检测 | `generated/middleware/FreeRTOSConfig.h` | `configCHECK_FOR_STACK_OVERFLOW 2U` |
| 波特率与位时序 | `generated/hal/mx_usart*.c`、`mx_fdcan*.c` | 与本文第 1 节一致 |
| CAN 帧格式 | `mx_fdcan2.c` | 若电机接 CAN2，需改回 `CLASSIC_CAN` |
| 时钟树 | `mx_rcc.c` | 144 MHz，FDCAN 时钟源 PCLK1 |

`generated/` 下的其它文件不要手改；需要改的行为一律通过 CubeMX 配置，或按设计在运行时初始化（例如由 Platform 层打开 CAN 中断）。

## 7. 原理图到位后的补全顺序

1. 确认电机型号、接口、总线、地址 → 填 `BOARD_MOTOR_*`。
2. 确认麦轮直径、减速比、每圈计数 → 填 `BOARD_WHEEL_DIAMETER_MM`，复核 `COUNTS_PER_REV`。
3. 确认 IMU 型号与接口 → CubeMX 加串口/DMA，再按 [代码架构.md](代码架构.md) 第 12 节新增设备。
4. 确认遥控接口 → 决定是否需要输入捕获或特殊波特率。
5. 确认上位机协议 → 再写 `app/protocol`。
6. 整车架空测试：先单电机点动，再四轮同向，最后逆解。

每一步完成后更新 [修改日志.md](修改日志.md)。
