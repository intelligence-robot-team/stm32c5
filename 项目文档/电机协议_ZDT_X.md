# 电机协议：张大头（ZDT）X 固件

> 来源：《ZDT_X42S 通讯指令手册》（自官方用户手册第 5 章整理）与本仓库 `Pcb-yun/zdt-v5-driver` 的协议常量交叉核对。
> 适用范围：X42S / X42 / Y42 的 **X 固件**。Emm 固件的速度与位置帧格式不同，本文件不涉及。
> **所有"★"标记的条目未经实物验证，见 [待确认问题.md](待确认问题.md)。**

---

## 1. 帧总则（串口形态）

```
[地址 Addr] [功能码] [数据 ...] [校验 0x6B]
```

- 地址：1~255，对应驱动器菜单 `ID_Addr`。
- 校验：出厂默认固定 `0x6B`；驱动器菜单 `Checksum` 还可选 XOR / CRC-8 / Modbus，**本工程只实现固定 0x6B**（P-3）。
- 多字节字段一律**大端**（高字节在前）。
- 应答：`[地址][功能码][返回数据][0x6B]`，返回数据 `02` 成功、`E2` 参数错、`EE` 格式错；动作完成时驱动器可主动上报 `9F`。

## 2. 命令与应答

### 2.1 电机使能（3.2）

```
发送：Addr | F3 | AB | EN(00/01) | SYNC(00/01) | 6B      共 6 字节
应答：Addr | F3 | 02/E2/EE | 6B                          共 4 字节
```
- `EN`：00 = 松轴，01 = 锁轴。
- `SYNC`：00 = 立即执行，01 = 缓存等待同步触发。

### 2.2 速度模式（3.5，X 固件）

```
发送：Addr | F6 | DIR | ACC_H | ACC_L | VEL_H | VEL_L | SYNC | 6B     共 9 字节
应答：Addr | F6 | 02/E2/EE | 6B                                      共 4 字节
```
| 字段 | 取值 | 说明 |
|---|---|---|
| `DIR` | 00 = CW，01 = CCW | 实际转向还受驱动器菜单 `Dir` 影响，见 P-5 |
| `ACC` | 0x0000 ~ 0xFFFF | 加速度，单位 RPM/s；0 表示用驱动器内部值 |
| `VEL` | 0x0000 ~ 0x7E30 | 0.1 RPM 单位，即 0 ~ 3230.4 RPM ★ 与手册标注"3000.0 RPM"矛盾（P-2） |
| `SYNC` | 00 / 01 | 01 时缓存，等 `FF 66` 广播触发 |

### 2.3 立即停止（3.15）

```
发送：Addr | FE | 98 | SYNC | 6B        共 5 字节
应答：Addr | FE | 返回数据 | 6B         共 4 字节
```

### 2.4 读实时转速（5.11）

```
发送：Addr | 35 | 6B                          共 3 字节
应答：Addr | 35 | SIGN | VEL_H | VEL_L | 6B   共 6 字节
```
X 固件单位 0.1 RPM，范围 0x0000~0x1388。

### 2.5 读实时位置（5.13）

```
发送：Addr | 36 | 6B                                   共 3 字节
应答：Addr | 36 | SIGN | POS[4] | 6B                   共 8 字节
```
- `POS` 4 字节大端，符号单独用 `SIGN` 表示。
- X 固件：角度值 = 位置值 / 10（单位 0.1°）。
- Emm 固件：角度值 = 位置值 × 360 / 65536，**不适用**本工程。

### 2.6 读状态标志（5.15）

```
发送：Addr | 3A | 6B                共 3 字节
应答：Addr | 3A | STATUS | 6B       共 4 字节
```
| 位 | 名称 | 含义 |
|---|---|---|
| bit0 | Ens_TF | 0 未使能，1 已使能 |
| bit1 | Prf_TF | 0 未到位，1 已到位 |
| bit2~7 | 手册未定义 | 不解析，原样保存在 `last_status` |

## 3. CAN 映射（★ 待实物确认，P-1）

### 推导

串口速度帧 9 字节，其中第 1 字节是地址。经典 CAN 数据域上限 8 字节，而把地址移到标准帧 ID 后正好剩 8 字节：

```
CAN 标准帧  ID = 节点地址
           数据域 = [F6][DIR][ACC_H][ACC_L][VEL_H][VEL_L][SYNC][6B]
```

其余命令同理，数据域为"串口帧去掉地址字节"：

| 命令 | CAN 数据域长度 | 内容 |
|---|---|---|
| 使能 | 5 | `F3 AB EN SYNC 6B` |
| 速度 | 8 | `F6 DIR ACC_H ACC_L VEL_H VEL_L SYNC 6B` |
| 停止 | 4 | `FE 98 SYNC 6B` |
| 读转速 | 2 | `35 6B` |
| 读位置 | 2 | `36 6B` |
| 读状态 | 2 | `3A 6B` |
| 应答 | 比串口少 1 | 去掉首字节地址 |

### 这个推导的可信度

- 支持：9 字节串口帧去掉地址恰好 8 字节，与经典 CAN 上限严丝合缝；多份第三方实现也按"ID = 地址"使用。
- 不确定：官方 X42S 手册只给了串口帧，CAN 章节未纳入本仓库。**必须实物验证**，验证方法见 P-1。
- 解析设计上做容错：解析函数若发现首字节等于本节点地址，会自动跳过再解析；即"地址在数据域"的固件也能收，但发送仍按"地址在 ID"。

## 4. 单位换算

| 量 | 公式 | 计划实现位置 |
|---|---|---|
| 线速度 → 0.1 RPM | `raw = |v_mm_s| × 600 / (π × D_mm)` | `zdt_set_speed()` |
| 0.1 RPM → 线速度 | `v_mm_s = raw × π × D_mm / 600` | `Motor_StepperZDT_OnFrame()` |
| 0.1° → mm | `distance_mm = pos / counts_per_mm` | 同上 |
| 每毫米计数 | `counts_per_mm = counts_per_rev / (π × D_mm)` | `Motor_StepperZDT_Init()` |

示例（D = 65 mm）：

```
v = 100 mm/s  → raw = 100 × 600 / (π × 65) = 294  (29.4 RPM)
pos = 3600    → 360.0° → 一圈 → distance = π × 65 = 204.2 mm
```

设计行为：`D = 0` 时 `counts_per_mm` 置 0 且 `configured = false`，`SetSpeed()` 拒绝运动且不发帧。

## 5. 协议与计划实现的对照

| 协议 | 代码 | 备注 |
|---|---|---|
| `F3 AB EN SYNC 6B` | `zdt_enable()` | 使能状态以 0x3A 回读为准，不在发送时乐观置位 |
| `F6 ...` | `zdt_set_speed()` | 方向由速度符号 + `dir_invert` 决定 |
| `FE 98 SYNC 6B` | `zdt_stop()` | 只在显式 Stop 时发；速度 0 走 F6 |
| `35 / 36 / 3A` | `zdt_request_feedback()` | 一次发三帧，建议 ≤ 50 Hz |
| 应答解析 | `Motor_StepperZDT_OnFrame()` | 任务上下文调用，不在中断里 |

## 7. 实物验证清单（上台架第一件事）

1. 用 CAN 分析仪发 `ID=1, data=F3 AB 01 00 6B`，看是否回 `F3 02 6B`。回帧即证明"地址在 ID"成立。
2. 发 `ID=1, data=F6 00 00 64 00 64 00 6B`（100 → 10.0 RPM），看电机是否低速转动。
3. 发 `36 6B`，确认回帧长度为 7 且末字节 0x6B。
4. 若第 1 步无应答：改驱动器 `Checksum` 为固定 0x6B、确认 `CAN_Baud` 与 `P_SERIAL=CAN1_MAP`，再试；仍无应答则考虑地址在数据域的固件，需要改发送侧（改动点只在 `zdt_*` 组帧函数）。

任何一步与本文不符，先更新 [待确认问题.md](待确认问题.md)，再改代码。
